## このライブラリの使い方

各手法は「**トリプレット（3点セット）**」で構成されます。

1. **手法（Technique）** — 攻撃の手口
2. **リスク要因（Risks）** — その手口を成立させる下地となる条件
3. **コントロール（Controls）** — 手口を防止・検知するセキュリティ対策

コントロールは2種類に分かれます。

- 🛡️ **防御的コントロール（Protective Controls）** — 攻撃を未然に防ぐ、設定ベースの対策
- 🔍 **検知的コントロール（Detective Controls）** — 攻撃を発見する、監視・検知の仕組み

**攻撃を分析するには**: 攻撃で使われた手法を本ライブラリで探せば、その手口を成立させたリスクと、防げたはずのコントロールがすぐに分かります。

対象は SDLC インフラを5つのコンポーネントに分けた **計81手法**です。

| コンポーネント | ID 接頭辞 | 手法数 |
| --- | --- | --- |
| 端末・IDE | T-E | 19 |
| VCS（バージョン管理システム） | T-V | 12 |
| CI/CD | T-C | 21 |
| レジストリ（コンテナ / アーティファクトレジストリ） | T-R | 13 |
| 本番・クラウド | T-P | 16 |

## コンポーネント別 攻撃手法

### 端末・IDE（ENDPOINT / IDE）

#### T-E001: 端末上での悪意あるコード実行（Malicious Execution on Endpoint）

**手法**: 攻撃者が開発者のワークステーション上で悪意あるコードを実行する。

**リスク要因**:

- 信頼できない IDE 拡張機能の利用
- 端末上での信頼できないソフトウェアパッケージの利用
- EDR が無い
- アプリケーションのサンドボックス化の欠如
- パッケージインストール時のスクリプト実行が有効
- パブリックレジストリからの直接ダウンロード

**防御的コントロール 🛡️**:

- フィルタリング機能を備えたローカルレジストリプロキシ
- IDE のサンドボックス化
- 署名済み拡張機能の必須化
- パッケージバージョンの固定
- メンテナの評判・健全性の自動チェック
- アプリケーションのホワイトリスト化
- パッケージインストールスクリプトの無効化（--ignore-scripts）

**検知的コントロール 🔍**:

- 端末上の EDR

#### T-E002: 端末へのフィッシング（Endpoint Phishing）

**手法**: 攻撃者が開発者にフィッシングを仕掛け、認証情報を盗んだりマルウェアを仕込んだりする。

**リスク要因**:

- 2FA・フィッシング対策の欠如
- セキュリティ意識向上トレーニングが無い
- 認証情報が平文で保存されている
- メールセキュリティ対策が無い

**防御的コントロール 🛡️**:

- MFA の必須化
- フィッシング耐性のある認証
- セキュリティ意識向上トレーニング
- メールセキュリティ（SPF, DMARC, DKIM）

**検知的コントロール 🔍**:

- 端末上の EDR

#### T-E003: 端末からのローカルシークレット・認証情報の窃取（Harvest Local Secrets / Credentials from Endpoint）

**手法**: 攻撃者が開発者マシンに保存された認証情報を抽出する。

**リスク要因**:

- 認証情報が平文で保存されている
- 本番環境の認証情報が開発者マシン上にある
- ローカル DLP が無い
- パスワード無しの SSH 鍵
- 環境変数に格納されたクラウド認証情報

**防御的コントロール 🛡️**:

- 認証情報マネージャーの利用強制
- 端末への本番認証情報の非配置
- 認証情報の暗号化保存

**検知的コントロール 🔍**:

- ローカル DLP
- 端末上の EDR

#### T-E004: 端末からのローカルデータの窃取（Harvest Local Data from Endpoint）

**手法**: 攻撃者が端末からソースコード・ドキュメント・その他の機微データを持ち出す。

**リスク要因**:

- ローカル DLP が無い
- EDR が無い
- 機微データがローカルに保存されている
- 保存データの暗号化が無い

**防御的コントロール 🛡️**:

- データ分類と取り扱いポリシー
- 保存データの暗号化

**検知的コントロール 🔍**:

- ローカル DLP
- 端末上の EDR
- ネットワーク監視

#### T-E005: 端末上での暗号資産マイニング（Cryptomining on Endpoints）

**手法**: 攻撃者が端末のリソースを暗号資産のマイニングに悪用する。

**リスク要因**:

- EDR が無い
- 信頼できないソフトウェアパッケージ
- リソース監視が無い

**防御的コントロール 🛡️**:

- アプリケーションのホワイトリスト化

**検知的コントロール 🔍**:

- 端末上の EDR
- リソース監視とアラート
- ネットワーク監視（マイニングプールへの接続を検知）

#### T-E006: ローカルマシンの CI ランナー登録（Register Local Machine as CI Runner）

**手法**: 攻撃者が侵害した端末をセルフホスト型 CI/CD ランナーとして登録する。

**リスク要因**:

- 任意のマシンをランナーとして登録できる
- ランナー登録の承認プロセスが無い
- ランナー登録トークンが保護されていない

**防御的コントロール 🛡️**:

- マネージドランナーのみの利用
- ランナー登録の承認ワークフロー
- ランナー登録トークンの保護
- ネットワークセグメンテーション（ランナーを端末から隔離）

#### T-E007: 端末からのローカル VCS アクセスの悪用（Abuse Local VCS Access from Endpoint）

**手法**: 攻撃者がローカルの git 認証情報を使って VCS にアクセスする。

**リスク要因**:

- VCS 認証情報が端末に保存されている
- 認証情報のローテーションが無い
- 過剰な権限を持つ VCS アクセス

**防御的コントロール 🛡️**:

- 認証情報マネージャーの利用強制
- 有効期限付きのきめ細かい PAT
- VCS への MFA 必須化

**検知的コントロール 🔍**:

- 監査ログ監視

#### T-E008: 端末からのローカル CI/CD アクセスの悪用（Abuse Local CI/CD Access from Endpoint）

**手法**: 攻撃者がローカルの CI/CD 認証情報を使って CI/CD システムにアクセスする。

**リスク要因**:

- CI/CD 認証情報が端末に保存されている
- 認証情報のローテーションが無い
- 過剰な権限を持つ CI/CD アクセス

**防御的コントロール 🛡️**:

- 認証情報マネージャーの利用強制
- 長期トークンではなく OIDC の利用
- CI/CD への MFA 必須化

**検知的コントロール 🔍**:

- 監査ログ監視

#### T-E009: ローカル AI ツールの悪用（Abuse Local AI Tools）

**手法**: 攻撃者が AI コーディングアシスタントを使ってコードを持ち出したり、悪意ある提案を注入したりする。

**リスク要因**:

- 信頼できない AI ツールの利用
- 利用許諾ポリシーが無い
- 過剰な権限を持つ AI ツール
- 機微なコードが AI サービスへ送信される

**防御的コントロール 🛡️**:

- 未承認 AI ツールを禁じる利用許諾ポリシー
- データ保護機能を備えた承認済み AI ツール
- AI 生成コードのコードレビュー

**検知的コントロール 🔍**:

- AI サービスへの接続に対するネットワーク監視

#### T-E010: 端末インフラの破壊（Endpoint Infrastructure Destruction）

**手法**: 攻撃者が端末のシステム・データ・設定を破壊または改ざんし、業務の混乱を引き起こす。

**リスク要因**:

- バックアップとリカバリが無い
- 過剰な権限を持つローカルユーザーアカウント
- EDR が無い
- システム完全性監視の欠如
- 重要なシステムファイルに対するアクセス制御が不十分

**防御的コントロール 🛡️**:

- 定期的な端末バックアップ
- 最小限のローカルユーザー権限
- オフラインでのバックアップ保管
- ファイルシステムのアクセス制御
- 端末の復旧手順

**検知的コントロール 🔍**:

- 端末上の EDR
- システム完全性監視

#### T-E011: Unicode を使った隠蔽コードインジェクション（Unicode Stealth Code Injection）

**手法**: 攻撃者が不可視の Unicode 文字（異体字セレクタ、ゼロ幅文字）を使い、エディタ上では表示されないが正常に実行される悪意あるコードを隠す。

**リスク要因**:

- 信頼できない IDE 拡張機能の利用
- コードレビューで不可視文字を検出できない
- 静的解析ツールが非表示文字を見逃す
- diff ツールが不可視コードを強調表示しない
- 目視によるコード検査への開発者の依存

**防御的コントロール 🛡️**:

- 不可視文字を可視化する IDE プラグイン
- Unicode 正規化を伴う静的解析
- 拡張機能のコード署名と検証
- 専用ツールを用いたコードレビューの必須化

**検知的コントロール 🔍**:

- コードレビューツールでの Unicode 文字検出
- コミット内の非表示文字の自動検出

#### T-E012: 端末への SOCKS プロキシ配置（SOCKS Proxy Deployment on Endpoint）

**手法**: 攻撃者が侵害した端末に SOCKS プロキシサーバーを配置し、被害者のネットワークと IP アドレスを経由して悪意ある通信を中継する。

**リスク要因**:

- EDR が無い
- ネットワークの egress 監視が無い
- 制限のないアウトバウンド接続
- 端末が社内ネットワーク内にある
- プロセス監視が無い

**防御的コントロール 🛡️**:

- アプリケーションのホワイトリスト化
- ネットワークセグメンテーション（端末を本番環境から分離）
- アウトバウンド接続の制限

**検知的コントロール 🔍**:

- 端末上の EDR
- egress 監視とフィルタリング
- 異常なネットワーク挙動の検知

#### T-E013: 隠蔽型 VNC（HVNC）の配置（Hidden VNC (HVNC) Deployment）

**手法**: 攻撃者がユーザーに気づかれずに不可視のリモートデスクトップアクセスを提供する隠蔽型 Virtual Network Computing を配置する。

**リスク要因**:

- EDR が無い
- プロセス監視が無い
- アプリケーションのサンドボックス化の欠如
- 特権ユーザーアカウント

**防御的コントロール 🛡️**:

- 最小限のローカルユーザー権限

**検知的コントロール 🔍**:

- 端末上の EDR
- プロセス監視とホワイトリスト化
- セッションアクティビティの監視
- 隠しプロセスの挙動分析
- 仮想デスクトップの検出

#### T-E014: WebRTC による P2P 制御チャネルの確立（WebRTC P2P Control Channel Establishment）

**手法**: 攻撃者が WebRTC のピアツーピア接続を確立し、NAT トラバーサルによって従来のファイアウォールを回避した直接制御を行う。

**リスク要因**:

- ブラウザ・アプリケーションで WebRTC が有効
- WebRTC トラフィックのネットワーク監視が無い
- NAT トラバーサルがファイアウォールルールを回避する
- EDR が無い
- P2P 接続がログに記録されない

**防御的コントロール 🛡️**:

- ネットワーク挙動分析
- 社内ブラウザでの WebRTC 制限
- STUN/TURN サーバーのホワイトリスト化

**検知的コントロール 🔍**:

- 端末上の EDR
- WebRTC トラフィックの監視
- ディープパケットインスペクション

#### T-E015: 拡張機能の自動更新の悪用（Extension Auto-Update Exploitation）

**手法**: 攻撃者が拡張機能の自動更新の仕組みを悪用し、ユーザーの操作なしに全ユーザーへ悪意ある更新を密かに配布する。

**リスク要因**:

- 拡張機能の自動更新が有効
- 更新の検証が無い
- 拡張機能パブリッシャーのアカウントが侵害されている
- 拡張機能のバージョン固定が無い
- ユーザーへの通知なしのサイレント更新

**防御的コントロール 🛡️**:

- 拡張機能更新の承認ワークフロー
- 拡張機能のバージョン固定
- 更新の署名検証
- 段階的な更新配布（カナリアテスト）

**検知的コントロール 🔍**:

- 拡張機能更新の監視とアラート
- 拡張機能マーケットプレイスのセキュリティ監視

#### T-E016: ブロックチェーンベースの C2 インフラ（Blockchain-Based C2 Infrastructure）

**手法**: 攻撃者がブロックチェーン取引（例: Solana, Bitcoin）を、テイクダウンや検閲が不可能な不変のコマンド&コントロールインフラとして利用する。

**リスク要因**:

- ブロックチェーン上の不変の C2 命令
- EDR が無い
- 暗号資産ノードへの接続が制限されていない

**防御的コントロール 🛡️**:

- ネットワーク挙動分析
- 暗号資産関連トラフィックの制限
- アプリケーションのホワイトリスト化

**検知的コントロール 🔍**:

- 端末上の EDR
- ブロックチェーン RPC 接続の監視
- 異常なブロックチェーンクエリの検知

#### T-E017: 正規サービスを悪用した C2（Legitimate Service Abuse for C2）

**手法**: 攻撃者が正規のクラウドサービス（Google Calendar, Pastebin, SNS, クラウドストレージ）をコマンド&コントロールチャネルとして利用し、検知を回避する。

**リスク要因**:

- 正規サービスが C2 悪用の観点で監視されていない
- 正規サービスのトラフィックに対する内容検査が無い
- サービスがセキュリティ制御でホワイトリスト化されている
- EDR が無い
- 正規サービスのデータにエンコードされたペイロード

**防御的コントロール 🛡️**:

- 正規サービスのトラフィックに対するディープコンテンツインスペクション

**検知的コントロール 🔍**:

- 端末上の EDR
- 通常と異なるサービス利用パターンの挙動分析
- ネットワークトラフィックの異常検知
- アプリケーションレベルの監視
- データ持ち出しの検知

#### T-E018: BitTorrent DHT を利用した C2（BitTorrent DHT for C2）

**手法**: 攻撃者が BitTorrent の分散ハッシュテーブル（DHT）ネットワークを利用し、シャットダウン不可能な分散型のコマンド配信を行う。

**リスク要因**:

- BitTorrent・P2P トラフィックが監視されていない
- DHT ネットワーク接続が通常の P2P トラフィックに見える
- EDR が無い
- 分散型 C2 はテイクダウンできない
- P2P プロトコルが制限されていない

**防御的コントロール 🛡️**:

- P2P プロトコルのブロック
- ネットワーク挙動分析
- アプリケーションのホワイトリスト化

**検知的コントロール 🔍**:

- 端末上の EDR
- BitTorrent トラフィックの監視とブロック
- DHT ネットワーク接続の検知

#### T-E019: 組織横断アクセスのための OAuth トークン悪用（OAuth Token Abuse for Cross-Organizational Access）

**手法**: 攻撃者が盗んだ OAuth トークンを使い、組織の境界を越えてユーザーになりすまし、持続的なトークンアクセスによって SSO/MFA の制御を回避する。

**リスク要因**:

- OAuth トークンがブラウザや認証情報ストアに保存されている
- サードパーティアプリに過剰な OAuth スコープが付与されている（「すべて許可」）
- OAuth トークンがデバイスや IP に紐づいていない
- 組織をまたぐ OAuth トークン利用が監視されていない
- ローテーションされない長期の OAuth リフレッシュトークン
- 企業の ID システムへ OAuth アクセスを持つサードパーティベンダー
- サードパーティ侵害時にトークンが失効されない

**防御的コントロール 🛡️**:

- OAuth スコープの最小化
- OAuth トークンバインディング
- OAuth アプリの承認ワークフロー
- 頻繁にローテーションされる短命の OAuth トークン
- サードパーティベンダーのセキュリティ評価
- OAuth アプリに対する条件付きアクセスポリシー

**検知的コントロール 🔍**:

- OAuth トークン利用の異常検知
- 組織横断の OAuth アクティビティ監視
- サードパーティ OAuth アプリの監査ログ記録
- OAuth スコープ昇格のアラート

### VCS（バージョン管理システム）

#### T-V001: VCS アクセス用の認証情報の悪用（Abuse Credentials for VCS Access）

**手法**: 攻撃者が窃取した認証情報を使って VCS にアクセスする。

**リスク要因**:

- 2FA / フィッシング対策の欠如
- 組織の公開リポジトリ内に認証情報が存在
- 組織メンバーの公開リポジトリ内に認証情報が存在
- ワークフローログ内に認証情報が存在
- 過去の情報漏えい
- fine-grained PAT が強制されていない
- 有効期限のない PAT

**防御的コントロール 🛡️**:

- MFA の必須化
- IDP / SSO の設定
- fine-grained PAT の強制
- PAT 有効期限の強制

**検知的コントロール 🔍**:

- 組織リポジトリに対する secret scanning
- 個人リポジトリに対する secret scanning

#### T-V002: なりすましコミット（Imposter Commits）

**手法**: 攻撃者が他の開発者になりすましてコードをコミットする。

**リスク要因**:

- commit signing が必須化されていない
- メール検証が強制されていない
- コードレビュープロセスがない

- CSPM/CNAPP

**検知的コントロール 🔍**:

- 監査ログ上の検知基盤

#### T-P010: 本番環境内でのネットワーク横展開（Network Lateral Movement Within Production）

**手法**: 攻撃者がネットワーク経由で本番システム間を移動する。

**リスク要因**:

- 脆弱なネットワーク分離
- 過度に緩い security group
- ネットワーク監視の欠如
- 未パッチのシステム

**防御的コントロール 🛡️**:

- ネットワーク分離
- micro-segmentation
- security group のハードニング
- 脆弱性管理

**検知的コントロール 🔍**:

- ネットワーク監視

#### T-P011: 本番環境からのシークレット窃取（Steal Secrets from Production Environment）

**手法**: 攻撃者が本番のシークレットストアにアクセスし、顧客のシークレット、トークン、クレデンシャルを持ち出す。

**リスク要因**:

- プロセスメモリ上でアクセス可能な暗号鍵
- 鍵保管用の hardware security module（HSM）の欠如
- シークレットローテーションポリシーの欠如
- 全顧客シークレットの集中管理
- 本番システム上の data loss prevention（DLP）の欠如
- egress トラフィック監視の欠如

**防御的コントロール 🛡️**:

- 暗号鍵を HSM（Hardware Security Module）に保管
- 鍵階層を用いた envelope encryption
- 顧客管理の暗号鍵（CMEK）
- シークレットの自動ローテーション（30〜90日）
- シークレットのセグメンテーション（顧客ごとの隔離）
- メモリ保護とダンプ対策コントロール

**検知的コントロール 🔍**:

- 本番システム上の DLP
- egress トラフィックの監視とフィルタリング
- 監査ログ上の検知基盤（本番）
- 大容量データ転送の検知

#### T-P012: 本番インフラの偵察（Production Infrastructure Reconnaissance）

**手法**: 攻撃者が本番インフラ、サービス、リソースを列挙し、標的の特定と攻撃計画を行う。

**リスク要因**:

- 列挙を許してしまう過剰な権限の IAM ロール
- 偵察活動の検知の欠如
- 公開されたクラウド metadata
- スキャンを許してしまうネットワーク分離の不足
- インフラの詳細を露呈する冗長なエラーメッセージ
- honeypot や欺瞞技術の欠如
- API 呼び出しへの rate limit の欠如

**防御的コントロール 🛡️**:

- 最小限の IAM 権限
- API の rate limiting と throttling
- ネットワーク分離（本番内部）
- metadata service へのアクセス制限
- 汎用的なエラーメッセージ（インフラ詳細を含めない）

**検知的コントロール 🔍**:

- 監査ログ上の検知基盤（本番）
- honeypot と欺瞞技術
- 列挙パターンに対する異常検知

#### T-P013: 本番環境からのデータ持ち出し（Data Exfiltration from Production）

**手法**: 攻撃者が本番環境から顧客データ、アプリケーションデータ、データベース、機密情報をネットワーク経由で持ち出す。

**リスク要因**:

- ネットワーク egress 監視の欠如
- 制限のない outbound ネットワークアクセス
- 本番システム上の DLP の欠如
- アクセス可能かつ監視されていないバックアップデータ
- DLP を回避するための暗号化チャネルの利用
- パブリックアクセス可能なクラウドストレージバケット

**防御的コントロール 🛡️**:

- バックアップの暗号化とアクセス制御
- SSL/TLS インスペクション
- データ分類と取り扱いポリシー
- ネットワーク分離（本番をインターネットから）
- CSPM/CNAPP

**検知的コントロール 🔍**:

- Network DLP
- egress トラフィックの監視とフィルタリング
- 大容量データ転送の検知
- データベースアクティビティ監視
- 監査ログ上の検知基盤（本番）

#### T-P014: 本番インフラの破壊（Production Infrastructure Destruction）

**手法**: 攻撃者が本番インフラ、データベース、ストレージ、構成を破壊し、深刻な運用障害とデータ損失を引き起こす。

**リスク要因**:

- 破壊的操作を許してしまう過剰な権限の IAM ロール
- バックアップおよびディザスタリカバリ計画の欠如
- 重要リソースに対する削除保護の欠如
- 監査ログ監視の欠如
- 重要インフラに対するアクセス制御の不足
- 破壊的操作に対する承認プロセスの欠如
- 本番から隔離されていないバックアップデータ

**防御的コントロール 🛡️**:

- 最小限の IAM 権限
- オフサイト/オフラインストレージによる定期バックアップ
- 重要リソースに対する削除保護
- 破壊的操作の承認ワークフロー
- イミュータブルなバックアップ
- ディザスタリカバリ手順とその検証
- リソースのタグ付けと保護ポリシー
- 本番ネットワークからのバックアップ隔離
- CSPM/CNAPP

**検知的コントロール 🔍**:

- 監査ログ上の検知基盤（本番）

#### T-P015: 永続化のための悪意あるサービスのプロビジョニング（Malicious Service Provisioning for Persistence）

**手法**: 攻撃者がオーケストレーションプラットフォーム（例: ArgoCD, Kubernetes）で新たな悪意あるサービスをプロビジョニングしたり、既存サービスにバックドアを仕込んだりして、永続化を確立する。

**リスク要因**:

- サービスプロビジョニングに対する承認ゲートの欠如
- 開発者が任意のサービスを作成可能
- サービス定義が監査されていない
- 新規サービス作成に対する異常検知の欠如
- 永続的なバックドアサービスが検知されないまま残存

**防御的コントロール 🛡️**:

- 新規サービスに対するデプロイ承認ゲート
- 全 IaC 変更に対するコードレビュー
- 承認済みサービスのベースラインリスト
- CSPM/CNAPP

**検知的コントロール 🔍**:

- 監査ログ上の検知基盤（本番）
- 新規サービス作成パターンに対する異常検知
- イミュータブルな監査ログ
- 定期的なサービスインベントリ監査

#### T-P016: サプライチェーンバックドア（sensor/agent の汚染）（Supply Chain Backdoor (Sensor/Agent Poisoning)）

**手法**: 攻撃者がセキュリティ sensor、agent、あるいはクライアントに配布されるソフトウェアにバックドアを注入し、全顧客に影響する下流のサプライチェーン侵害を引き起こす。

**リスク要因**:

- 配布ソフトウェアに対するバイナリ署名検証の欠如
- 検証なしに自動デプロイされる顧客向けアップデート
- sensor バイナリに対する provenance attestation の欠如
- リリースに対する複数者承認の欠如

**防御的コントロール 🛡️**:

- 全配布バイナリに対するコード署名と検証
- provenance attestation（SLSA Level 3+）
- 検証を伴う顧客制御のアップデートポリシー
- リリース署名における職務分掌
- イミュータブルなビルドログと attestation

**検知的コントロール 🔍**:

- sensor/agent リリースに対する複数者承認
- ビルドインフラの定期的なセキュリティ監査

## 攻撃分析での使い方（例: Shai-Hulud-2）

実際の攻撃を、本ライブラリを使って分析する手順の例です。

**ステップ1: 使われた手法を特定する**

- T-C003: PWN Request / Poisoned Pipeline Execution
- T-C005: ワークフローからの secret の窃取
- T-R004: 悪意あるパッケージの公開
- T-E001: 端末上での悪意あるコード実行
- T-E003: 端末からのローカルシークレット・認証情報の窃取
- T-E006: ローカルマシンの CI ランナー登録

**ステップ2: 各手法を本ライブラリで調べる**

各手法の項目を見れば、次が分かります。

- その手口を成立させたリスク
- その手口を防げたはずのコントロール

**ステップ3: 防御計画を作る**

使われた手法のコントロールをすべて洗い出します（例）。

- ブランチ保護ルール（VCS）
- fork からのワークフローに明示的な承認を要求（VCS）
- ワークフローでの OIDC 設定
- runner 上のランタイムエージェント
- Trusted Publishing
- 端末上の EDR
- ローカル DLP
- マネージドランナーのみの利用

**ステップ4: 攻撃経路に基づき優先順位を付ける**

最も重要な経由点（pivot point）を断つコントロールから着手します。

1. OIDC（CI/CD からの secret 窃取を防ぐ）
2. Trusted Publishing（レジストリ侵害を防ぐ）
3. EDR（端末侵害を検知する）
4. ネットワークセグメンテーション（本番へのピボットを防ぐ）
