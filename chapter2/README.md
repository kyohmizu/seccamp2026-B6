## 2-1 脅威モデリング

### 脅威モデリングの考え方

脅威モデリングは、システム全体を俯瞰し、攻撃対象となり得る領域（アタックサーフェス）や攻撃手法を事前に予測・特定する構造的な取り組みです。Adam Shostack は、Four Question Framework と呼ばれる以下の4つの問いに答える基本プロセスとしてこれを定式化しました。特定の技法に依存せず、STRIDE などの技法はこの枠組みの内部で組み合わせて適用します。

1. **何を作っているか（What are we working on?）**: システムの構成要素、および要素間のデータフロー・処理プロセスを定義します。データフロー図（DFD）やアーキテクチャ図に信頼境界（Trust Boundary）を設定することで、外部からの侵入経路となり得る領域が明確になります。
2. **何が起こり得るか（What can go wrong?）**: システムに潜む潜在的な脅威を抽出します。脅威の抽出・整理手法には複数のモデルが存在し、目的に応じて選択・適用します。
   - **STRIDE**: なりすまし（Spoofing）、改ざん（Tampering）、否認（Repudiation）、情報漏洩（Information Disclosure）、DoS（Denial of Service）、権限昇格（Elevation of Privilege）の 6観点から、要素ごとに漏れなく脅威を列挙する汎用的な手法。
   - **Attack Tree**: 攻撃者の最終目標（例: 本番環境への悪性コード到達）を頂点とし、それを達成する手段を階層的に分解して侵入パスを特定する手法。
   - **PASTA**: 攻撃シミュレーションからビジネスリスク評価までを段階的に進めるプロセス指向の手法。
   - **攻撃カタログとの照合**: MITRE ATT&CK、OSC&R、SITF、OWASP Top 10 CI/CD などの既知の攻撃技術フレームワークを参照し、脅威を網羅的に検証する手法。
3. **どう対処するか（What are we going to do about it?）**: 抽出した脅威に対し、低減（Mitigate）、除去（Eliminate）、移転（Transfer）、受容（Accept）の 4アプローチから対策を選定します。すべてのリスクを一律に遮断するのではなく、影響度と発生可能性に基づき優先順位を設定します。
4. **妥当性を検証できたか（Did we do a good job?）**: システム設計と構成図の整合性、脅威抽出の網羅性、および選定した対策の記録・追跡状況を多角的に評価します。

脅威一覧の網羅性そのものは最終目的ではありません。脅威モデリングの真の価値は、完全な脅威リストの作成以上に、関係者がシステム構造の理解を深め、設計段階の脆弱性に自主的に気づくプロセスそのものに存在します。セキュリティ専門家の有無に関わらず、開発・運用に携わるメンバーが多角的な議論を重ねること自体が極めて重要な成果となります。Threat Modeling Manifesto（脅威モデリング宣言）において、「単なるセキュリティのスナップショット取得よりも深い理解の獲得」「一回限りの成果物よりも継続的な洗練」が原則として掲げられているのも本質的な理由は同じです。
