# 解答: cooldown で公開直後の依存を避ける

公開直後のパッケージバージョンを一定期間インストール対象から除外し、悪性バージョン（例: `1.0.1`）が公開された直後の更新タイミングで誤って取り込まれるリスクを回避します。

## npm（frontend/.npmrc）
```ini
# frontend/.npmrc
min-release-age=7
```
`min-release-age` オプションは npm 11.10.0 以降で利用可能です。設定値には**日数**を指定します（数値のみを記述し、`7d` のような単位接尾辞は付与しません）。パブリッシュから指定日数（例: 7日）が経過していないバージョンは、解決およびインストールの対象から除外されます。

## pnpm（pnpm-workspace.yaml）
pnpm では `minimumReleaseAge`（分単位）で設定します。pnpm 11 以降ではデフォルトで 1日（1440分）の待機期間が有効化されています。

## ポイント
- Dependabot や Renovate などの依存関係自動更新ツールを併用する場合は、それらツール側の cooldown 設定（Renovate の `minimumReleaseAge` 等）も揃えます。揃えないと、更新 PR は新バージョンへ上げようとする一方でインストール側の cooldown が弾くため、install できない更新 PR が作られ続けます。
- 組織横断で本設定を強制適用するには、共有設定や組織ポリシーとして全リポジトリへ展開します（シフトダウンの推進）。
- cooldown は「依存更新時に公開直後のパッケージ適用を回避する」対策であり、`npm ci` による完全固定（演習03）や lockfile 差分のレビューと組み合わせることで多層防御を実現します。

## 動作確認
- `frontend/.npmrc` に `min-release-age` を設定した状態で、公開直後の新バージョンが自動解決・採用されないことを確認します。
- ローカル環境で検証する場合は、malicious-dependency のローカル版 `local/defenses.sh`（cooldown パターン）を実行し、公開直後の `1.0.1` が経過日数のしきい値未満として不採用処理される挙動を確認します。
- npm CLI 単体で確認を行う場合は、`min-release-age` に大きめの値（例: `365`＝365日）を設定した上で、直近でパブリッシュされたバージョンを含むパッケージに対して `npm install` を実行し、設定期間未満のバージョンが解決対象から除外されて直前のバージョンが選択・インストールされる挙動を確認します。
