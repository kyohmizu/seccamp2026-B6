# 演習14: 攻撃デモのフォレンジック

攻撃を受けた後、**防御側が自分たちのインフラのログと監視から、悪性な挙動をどこまで調査できるか**を体験します。

証跡には「防御側が実際に使えるもの」と「使えないもの」がある点に注意してください。攻撃デモでは、分かりやすさのために目立つ痕跡（マーカーファイルの生成、警告メッセージの表示）をわざと出しており、攻撃者側の C2 受信ログも参照できるようにしています。しかし実際の攻撃では、攻撃者はこうした痕跡を残さず、C2 側のログは防御側からは見えません。**防御側が実際に頼れるのは、パイプラインのログ・ネットワークの通信記録・ランタイム監視といった、自分たちで取得する証跡**です。この演習では、それらから攻撃を追います。

この演習は、実環境での完全な調査よりも、防御側が使える証跡・手法・ツールを理解することに主眼を置きます。環境が許せば実際に試し、難しければ方法論とツール例を整理するだけでもかまいません。

## 課題
1. **静的解析**: 疑わしいパッケージを入手できた場合の調査として、`registry/expense-format-evil/` のコードを読み、いつ・何を・どこへ送るか（インストール時／実行時の通信、メタデータサーバへのアクセス）を把握します。
2. **パイプラインのログ**: Cloud Build のログを詳細化し（`npm install --foreground-scripts` 等）、インストール中に想定外のスクリプトが実行された痕跡を確認します。攻撃者が出力を抑制した場合、ここに何が残るかも考えます。
3. **ネットワークの通信記録**: VPC Flow Logs / Cloud NAT ログで、ワークロードから外部への通信を調べ、未知の宛先（C2）への通信を特定します。あわせて、メタデータサーバ（`169.254.169.254`）へのアクセスはネットワークログに現れないことを確認します（リンクローカルアドレスで、通常のネットワークを経由しないため）。
4. **ランタイム監視**: eBPF ベースの監視を導入し、プロセス起動・ファイルアクセス・外向き接続を捕捉します。ネットワークログでは見えないメタデータアクセスや、インストール時のプロセス実行を、ここで捉えられることを確認します。
5. **見えるもの・見えないものの整理**: 各証跡から攻撃の何が分かり、何が分からないか（例: 送信されたデータの中身は、暗号化されていれば宛先と通信量しか分からない）を整理します。

## 検証
- どの証跡（パイプラインのログ・通信記録・ランタイム監視）で、攻撃の何が分かるかを説明できること。
- メタデータサーバへのアクセスがネットワークログに現れず、ランタイム監視でしか捉えられない理由を説明できること。
- 各証跡について「見えるもの／見えないもの」を整理できること。

## 発展
- **遮断して差分を見る**: Egress 制限で C2 への通信を止め、遮断された記録を証跡として確認します。
- **アラート化**: ランタイム監視で、メタデータアクセスや未知の宛先への通信をアラートにします。
- **デモ痕跡との対比**: マーカーファイルや C2 受信ログ（＝実運用では使えない情報）と、防御側の証跡（フローログ・ランタイム監視）を突き合わせ、防御側の証跡だけで攻撃の全体像をどこまで復元できるかを確認します。
